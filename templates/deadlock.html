    Learn more · waiting vs circular wait vs deadlock
    • Waiting — a process is blocked until a resource is free. Normal, and it usually ends.
    • Cycle in the graph — P1 waits for P2 … waits for P1. With single-instance resources a cycle is a deadlock.
    • With multiple instances a cycle is only a warning sign: another process may free an instance (try “Cycle, but no deadlock”).
    • Deadlock — a set of processes that can never finish, because each waits for something only another member can release.
    • Safe state — some order lets every process get its maximum claim and finish. Unsafe is not yet a deadlock, but it can become one.
    How this lab works · the four ways to handle deadlock
    • Prevention (by design) — lock ordering breaks circular wait. Avoidance (at each request) — Banker's algorithm refuses unsafe grants. Detection (every 0.5 s sample) — the several-instance algorithm. Recovery (after detection) — terminate a victim or pre-empt a resource.
    • Only transaction processes take locks; a blocked process waits for one request at a time; freed instances go to waiters in FIFO order.
    • Detection: Work = Available; finish any process whose request ≤ Work and add back its allocation. Processes that can never finish are deadlocked.
    • The detector raises WARNING as soon as a deadlock exists and CRITICAL after it persists 3 s. Resources A and B are also used by web requests, so a deadlock on them slows and fails the simulated service.

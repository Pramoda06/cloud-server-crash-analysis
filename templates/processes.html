Process states now

What each state means
  • NEW — just created by fork(), not yet runnable.
  • READY — runnable, waiting in the run queue for a vCPU.
  • RUNNING — on a vCPU now.
  • WAITING — sleeping until disk I/O or a page-in completes.
  • BLOCKED — waiting for a lock held by another process.
  • SLEEPING — idle, nothing to do.
  • HUNG — still exists and keeps its memory, but makes no progress and serves nothing. Its supervisor does not notice, because it never exited — it has to be killed, then restarted.
  • RESTARTING — being re-created by its supervisor; TERMINATED — exited (exit code shown).
  • These are the simulator's states. Linux reports similar ones (R, S, D, Z) in ps.
Kill vs Crash vs Hang
  • Kill — another process sends SIGKILL (exit code 137). It cannot be caught or ignored.
  • Crash — the process faults itself, e.g. an invalid memory access raises SIGSEGV (exit code 139; on Linux it may leave a core dump).
  • In this simulator both end the same way: TERMINATED, resources and locks released, no automatic restart — use Restart. Only the cause and the exit code differ.
  • Hang — nothing exits: the process stays alive (HUNG) but does no work, so nothing notices and Restart does not apply. It must be killed first.
